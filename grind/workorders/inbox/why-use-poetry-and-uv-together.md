# Why are we using both poetry and uv?

This project uses both `uv` and `poetry`. Why? Should we consolidate to one or the other?

## Research

UV is a blazing-fast, Rust-based Python package manager and resolver, often 10–100x faster than traditional tools. Poetry is a mature, feature-rich Python-written tool focused on robust dependency management and publishing. UV excels in speed and replacing pip, pyenv, and pipx, while Poetry offers better, more established workflow for library publishing.Key Differences Between Poetry and UVSpeed & Performance: UV is "blazingly fast" due to its Rust implementation and aggressive caching, making it vastly superior for large dependency trees. Poetry is considered slow in comparison.Technology & Setup: Poetry is written in Python, requiring a Python environment to start. UV is a single, standalone binary written in Rust.Workflow Scope: UV functions as a universal tool that replaces pip, virtualenv, pipx, and pyenv. Poetry is a dedicated dependency management tool focusing on pyproject.toml and publishing to PyPI.Dependency Resolution: UV boasts a faster, more efficient resolver that often uses less memory (10–50MB) compared to Poetry (1–2GB).Virtual Environments: Poetry creates its own virtual environments outside the project directory. UV manages environments efficiently within the project, often preferring a uv.lock file that is more "portable" than Poetry’s approach.When to Use WhichChoose UV if: You need extreme speed, work on large projects with many dependencies, or want a single tool to replace pip and pyenv.Choose Poetry if: You are building and publishing complex packages to PyPI, require mature documentation, or prefer a stable tool with a long history in the Python community.10 sitesPoetry vs UV. This allows you to verify that uv.lock and poetry.lock produce the same versions.Standardized pyproject.toml: If you use the standardized [project] table (PEP 621) in your configuration, both tools can often read the same file. This makes them interchangeable for different parts of your workflow, such as using uv for CI/CD speed and Poetry for local publishing.When to Keep BothLibrary Publishing: If you rely on Poetry's specialized publishing features for PyPI, you can keep Poetry as your "build system" while using uv for faster daily development.CI/CD Optimization: Use uv in your GitHub Actions or CI pipelines to slash build times (often by 40-60%), even if your local development environment still uses Poetry.Is it Recommended?While possible, it is generally better to commit to one tool once your project stabilizes to avoid configuration drift and team confusion.
